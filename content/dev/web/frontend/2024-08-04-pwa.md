# 목표

* 위에 화면까지 (아이폰 상단 노치부분) 꽉 채워서 보여주기
* 앱 자체의 스크롤 방지


&nbsp;


---
&nbsp;

1. **Safearea**  
상단은 노치부분, 하단은 스와이프바를 가리킴 (예.`env(safe-area-inset-top)`)

2. **CSS, viewport-fit**


    &nbsp;
    

    1. **`viewport-fit`** 
        
        ```html
            <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover, user-scalable=no" />
            <meta name="apple-mobile-web-app-capable" content="yes" />
            <meta name="apple-mobile-web-app-status-bar-style" content="black-translucent" /> 노치부분 투명하게
        ```
        
    &nbsp;
    
    2. **`env(safe-area-inset-top)`**
        
        기기의 노치, 스와이프 부분 정도의 너비를 구해주는 css값
        
        head태그 안에 meta 태그 중 `viewport-fit=cover` 값을 넣어야 사용 가능하다.
        
        *위의 보기는 safe-area-inset-top이니까 노치부분의 높이를 의미함*
        
        padding에 이 값을 넣으면 그 노치부분이 차지하는 만큼 패딩이 들어감
        
        margin을 넣으면 노치만큼 margin이 들어감 
         
        &nbsp;
        
        처음에 이런 변수를 생각하지 못하고 작업했기 때문에, 

        계속해서 padding때문에 화면을 넘어가 overflow가 생겨 스크롤이 생겼다.
        
        &nbsp;
        
        **✚  Modal overlay**
        
        노치부분에만 overlay 배경 적용이 안됐다. 

        &nbsp;

        모달을 띄울 때, 모달 overlay 부분도 고려해야 한다.
        
        &nbsp;

        
        body태그에 이미 padding-top에 env(safe-area-inset-top) 값이 설정되어 있어서 overlay 배경이 그만큼 아래로 내려갔다.
        
        

        그래서 배경을 env(safe-area-inset-top) 만큼 끌어올리고 (top) 높이를 그만큼 눌리도록 했다.
        
        ```css
        .overlay {
        	top: calc(0px - env(safe-area-inset-top));
        	height: calc(100% + env(safe-area-inset-top));
        }
        ```
        
         &nbsp;
    3. **`overscroll-behavior: none;`**
        
        overflow가 됐을때 스크롤 방지
