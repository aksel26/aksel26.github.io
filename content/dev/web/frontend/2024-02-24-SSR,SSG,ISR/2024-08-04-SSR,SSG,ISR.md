### 1. SSR (Server-Side Rendering)

특징: 매 요청 시 서버에서 HTML을 생성해 제공.

장점: 실시간 데이터 반영, SEO 친화적.

단점: 초기 로딩 속도가 느림(서버 부하).

**활용 사례:**

1.  사용자별 데이터를 표시해야 하는 페이지 (대시보드, 프로필).

2.  실시간 데이터가 중요한 페이지 (주식, 경기 점수).

3.  동적 콘텐츠 + SEO가 중요한 경우 (뉴스, 블로그).

### 2. SSG (Static Site Generation)

특징: 빌드 시 HTML을 정적으로 생성, 클라이언트에 정적 파일 제공.

장점: 로딩 속도가 빠르고, SEO에 최적화.

단점: 데이터 변경 시 재배포 필요.

**활용 사례:**

1.  변경이 적은 페이지 (랜딩 페이지, 문서 페이지).

2.  SEO가 중요한 정적 콘텐츠 (블로그, 제품 소개).

### 3. ISR (Incremental Static Regeneration)

특징: 초기 정적 파일 제공 후, 지정된 주기에 따라 페이지를 재생성.

장점: SSG의 속도와 SSR의 데이터 갱신 장점 결합.

단점: 즉각적인 데이터 반영은 어려움.

**활용 사례:**

1.  자주 갱신되지만 실시간성이 덜 중요한 페이지 (블로그 조회 수, 제품 가격).

2.  최신 데이터 유지가 필요한 페이지 (뉴스, 이벤트).

### SSR / SSG / ISR 비교 요약
| 렌더링 방식 | 데이터 최신화   | 로딩 속도 | SEO  | 적합한 페이지 유형                     |
|-------------|-----------------|-----------|------|---------------------------------------|
| SSR         | 요청 시 매번    | 느림      | 좋음 | 동적 데이터, 사용자별 페이지          |
| SSG         | 빌드 시         | 빠름      | 좋음 | 정적 콘텐츠, 변경이 드문 페이지       |
| ISR         | 지정된 주기마다 | 빠름      | 좋음 | 자주 변경되는 콘텐츠, 뉴스, 이벤트   |
